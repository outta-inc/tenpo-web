# TENPO/START 広告LP — アプリ引き継ぎ v1（接続レビュー案）

2026-11-26 / ChatGPT。PR #53 の確認版。現行アプリ本体は未変更。配備・広告配信は行わない。

## 体験
1. LPで開業段階と知りたいことを選択し、試算する。
2. 「入力を確認して続ける」で、この試算で本人が入力した数字、明示的に選んだ段階、確認候補のみを表示。
3. 本人が内容を確認した後に本体へ移動する。現在は同じLP内の受取確認画面まで（試作）。
4. 本体に接続する際は、既存の初回5問の未回答項目だけを聞き、確かめた後に既存計算処理で試算する。本体に計画がある場合は無断更新しない。
5. 入口の検索意図はUIの出し分け用。開業段階や業態の本人の回答とは区別。

## 通信・保存
- 本番接続は、LPと本体が同一オリジン start.tenpo-os.com で配備され、受取側が実装・受入された後だけ有効化。
- 明示的な確認後に専用の sessionStorage キー（案: tenpo-start:lp-handoff:v1）へ一時保存して同じタブで本体へ遷移する。保存できない時は警告してLPに留まるか、データを引き継がず本体を開く選択肢を出す。
- URL、広告タグ、第三者サービス、サーバーに入力内容を送らない。氏名、メール、ID、物件資料、相談内容、広告識別子を含めない。
- handoff-contract.mjs の parse で型、列挙値、範囲、余分なフィールド、重複、期限（30分）を検証。失敗したデータを反映しない。
- 受取確認を終える前は計画ストレージを変更しない。採用・破棄の後に一時キーを削除し再適用を防止。仮の入力値、無効な値、結果だけを確定値として送らない。初期表示のステージは未確認として送らない。
- 現在の確認版はメモリ内だけで処理し、一時キーにも書き込まない。公開アプリリンクはデータを含まない。

## 本体側受取のガード
- ローカルの S._u / S._uOld / IVS.answers および保存済み計画の有無を確認する。認証済みならアカウント側の計画・既存の同期競合処理も確認。
- 既存の計画があれば「今の計画を開く」を既定とし、別の試算候補は独立した確認画面に留める。既存1計画仕様のため、利用者の明示確認なしに置き換え・同期しない。
- 新規の場合も IV.setAnswer など既存の検証・保存の入口を使う。S、IVS、DBへ未確認の値を直接書き込まない。
- 対象機能を開く: sales→初回試算・計算のもと、property→物件の比較または家賃の入力、capital→お金、check→やること、contractCheck→契約前の確認（物件未選択の場合はまず選択）、review→開店後の振り返り。必要条件未達なら次の1問だけ出す。
- 認証・既存計画との競合・オフライン・戻る操作の受入が終わるまでは本番接続しない。
- LPの簡易試算は本体の昼夜・費用分解等を省略した仮の計算。引き継ぎは元の入力値のみ、本体の正式な計算で結果を再表示する。
