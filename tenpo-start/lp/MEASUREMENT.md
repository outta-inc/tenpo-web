# TENPO/START 広告配信前の計測設計（11/26・レビュー案）
PR #53。広告配信停止のまま。START 月1万円（Google Ads 日額328円）。外部広告タグ、DB、現行の匿名集計への変更はなし。

## 検証したいこと
「LP到達→価値の理解→試算→本体→計画の保存」。登録ボタンやログインを登録成果と混同しない。
初回はカフェ・飲食店・開業資金を中心に、月内の成果件数が少ないことを前提に絶対数と離脱箇所を見る。

| 事象 | 成立条件 | 分類 |
| --- | --- | --- |
| lp_view | 許可されたLPを表示 | 分母 |
| trial_changed | 有効な数値を本人が変更し結果が更新された（初期表示は除く） | 中間 |
| handoff_review | 引継ぎ内容確認を実際に開いた | 中間 |
| handoff_confirm | 本人が確認を押し一時保存に成功 | 中間 |
| app_received | 本体で有効なパケットを受け取った | 中間 |
| plan_ready | 既存の初回5問から初めて本体の計画が作成された | 中間 |
| first_plan_saved | アカウントに計画が存在しないという start_get の結果を得て、start_save が成功した | 主成果候補 |
 
既存利用者のログイン、同期、競合上書き、登録キャンセル、相談文作成、ボタン押下だけを主成果に数えない。
first_plan_saved は「初回のアカウント計画保存」であり、新規ユーザー登録そのものと同一ではない。LP経由の主成果として採用する前に実機で確認する。
相談文準備とLINE送信完了も別。Google Ads のコンバージョンの primary/secondary の設定は配信前の別承認。月額予算を変えない。

## 匿名集計の方針
既存 PR #52 の statTick は初回起点週・業態・6事象を送る。既存の集計はそのまま保持する。
LPは、広告に設定する固定の ?src=ads&intent=cafe 等（カフェ・飲食店・資金等の許可された分類のみ）を使う設計案。受取確認と実際の遷移を区別する。
イベントに含める候補は event / cohort（JST週の月曜）/ source / intent の4項目のみ。個人・端末ID、広告クリックID、検索語句、URL全文、金額、物件、連絡先を送らない。
src は固定の経路表示で、広告プラットフォームの厳密なクリック帰属ではない。第三者がURLを開くこともあるため、概数として扱う。
同じセッションの二重計測防止、途中離脱、保存拒否、戻る操作、同時タブ、TTL、再訪、登録結果の処理を本番接続前に検証。funnel-contract.mjs は候補の純粋関数であり、実際のブラウザ永続化、ページ間連携、バックエンド送信は未接続。
識別情報なしの集計はユニーク利用者数や厳密な個人別ファネルではない。割合は同一定義の集計同士の参考値に留め、7日再訪は既存指標と混同しない。

## 公開ゲート
- 現行ポリシーには匿名集計の説明の未整備がある（PR #52）。通知・ポリシー・同意要否を先に整合。案では明示許可がない限り新しい計測を送らない。
- リリース許可、実際の本番ドメイン、説明確認、同意の全てを満たし、DNT/GPC/nostat/自動テストでは送らない。拒否でもアプリ機能は同じ。
- 匿名の新しいDB/RPCを作る場合は別PR。列挙値・未来週・レート制限・権限をサーバーでも検証。金額や識別子を受け付けない。
- Google Adsの実際の広告コンバージョン計測には別途、利用条件・同意とクリック帰属の設計を確認する。匿名集計だけで広告管理画面のコンバージョン数を直接取得できるとは扱わない。タグ、API、イベント送信は現在OFF。
- LP/本体の実接続、既存計画保護、スマホ実機、公開URL、計測イベントの照合を通過し、広告の配信開始は別途承認を受ける。

テスト: funnel-contract.test.mjs に許可リスト、JSTの週境界、プライバシーゲート、重複、順序、送信候補の4項目のみを記録。ツール内で同じコードを評価し 40 件のassertを確認。ネットワーク、DB、Google Ads との実接続は未試験。
