# TENPO/START 計画アプリ（plan/index.html）の点検道具

計画アプリは `tenpo-start/plan/index.html` の1つのファイルが正本です（画面・見た目・動き・埋め込んだヒアリング）。
ヒアリングの質問だけは `tenpo-start/interview-src/` が元で、`embed.mjs` で index.html の `/*IV:BEGIN*/`〜`/*IV:END*/` に入れます。そこは直接直さないでください。

2026/11/23 に、版ごとに後ろへ重ねていた上書き（同じ関数の定義し直し・包み直し・後から足していた見た目）を、1つの定義ずつにまとめました。今後は該当する関数を直接直してください。

## 点検のしかた
`tenpo-start/` で `python3 -m http.server 8765` を動かしてから、Playwright（Python）で次を実行します。

- `python3 crawl.py <0〜7>`：サンプル5業態（a・d・t・c・b）と、ヒアリングに答えた3業態（カフェ・持ち帰り・サロン）の8通り。全タブ・9つの中を開き、画面のボタンを押して回り、ページのエラー・「undefined／NaN」などの表示・横のはみ出しを出します。何も出なければ合格。
- `python3 formula.py [幅 ...]`：試算の式と合計がそろうかの点検（2026/11/25）。38通りの業態・曜日で、最初の試算の画面・＋／−・計画のページ・公庫に出す下書きの式を掛けて足した数が、出している月の売上と同じかを確かめます。丸めていない小数（1.1666…）や NaN が画面に出ていないかも見ます。幅を省くと 393。PCの幅も見る時は `python3 formula.py 393 1280`。「NG」が出なければ合格。
- `python3 stat.py`：進み具合を数える所の点検（2026/11/25）。17件。送り先はこの点検の中で受け止めるので、本番には届きません。
- `python3 wording.py`：4業態の全画面で、もう使わない言葉（家賃に回せる額・参考額・手元に残したい額）が残っていないかを探します。公庫の制度の「上限」だけが出れば合格。
- `walk2.py`：ヒアリングを最後まで答える手順（crawl.py が使う）。
- `node unused.js ../plan/index.html`：どこからも呼ばれていない関数を一覧にします（`cut` を付けると消す）。
- `node dedup.js ../plan/index.html`：同じ名前で定義し直された関数の、古い方を消します。

## 式と合計をそろえる決まり（2026/11/25）
- 画面に出す式（金額 × 人数 × 日数）は、掛けて足すと、出している月の売上と同じになるようにする。式は `salesLines(r)`（売り方ごとに1行）から作り、画面ごとに別々に組み立てない。
- 人数・件数は `qn()` で出す：ちょうどの数ならそのまま、小数1桁で表せればその数、どちらでもなければ「約」を付ける。「約」が付かない数は、式と合計が合う。
- 仮に置く人数は、ちょうどの数にそろえる（`ivWholeF`。12席 × 1.2回 ＝ 14.4人 → 14人）。そろえるのは仮の数と、いまのお店の実績から置いた数だけ。答えた数・自分で入れた数・数えた数は動かさない。
- ＋／−で決めた人数は、回転数や埋まり具合に直す時に丸めない（丸めると14人が14.04人になる）。画面に出す時だけ `rd2()`（小数2桁）・%は小数1桁に丸める。
- 直したら `python3 formula.py 393 1280` を流す。

## 進み具合を数える（2026/11/25）
松尾さん「使われ方を数字で見る」。事務局アプリ（店 → 使われ方）に、初めて開いた数と、そこから何割が進んだかが出ます。
- 数えるのは6つ：初めて開いた（`open`）・5問を終えた（`iv_done`）・物件か家賃を入れた（`place`）・登録した（`signup`）・相談の文を用意した（`consult`）・7日以上あとに、もう1度開いた（`back7`）。
- 送るのは「出来事の名前・初めて開いた週の月曜（日本時間）・業態の大項目」の3つだけ。入れた内容・相談番号・アカウントは送りません。受ける側（TENPO/OS の `api.start_stat_put`。箱 `db/box-usage-v0.2`）も、人や端末を見分ける番号を持ちません。
- 端末ごとに1回だけ。送ったかどうかは、その端末の中（`tenpo-start:stat:v1`＝初めて開いた時刻と、送った印）に覚えます。
- 届かなかった時：通信そのものが通らなければ、その場でもう1度だけ。それでも届かない・断られた時は、次に開いた時に試します。届かなかった回数は `STAT.fail` に残ります（握りつぶさない）。数える所でつまずいても、アプリは止めません。
- 送らない時：手元と試験（localhost・自動操作）、番地に `?nostat=1` がある時、ブラウザで「追跡しない」（Do Not Track・GPC）にしている時。**本番を自分で確かめる時は `?nostat=1` を付けて開く**（数が増えないように）。
- アプリの中の説明：「知っておいてほしいこと」に、数だけを数えていること・だれの端末かは記録しないこと・入れた内容は送らないことを書いています。
- 読み方の注意：数え始めは 2026/11/25。その前に開いて、その後開いていない端末は入りません。送り口は外から呼べるので、数は目安です。
- 直したら `python3 stat.py` を流す。

## 計算の考え方（2026/11/22〜23）
- 家賃は実際の物件か、見た家賃（`refRent`：選んだ物件 → 見た家賃）。「家賃に回せる額」は使わない。
- 答えは「続けるのに1日に何人要るか」（`hmNeed`）。家賃が無い時だけ「家賃を払う前に残る額」。
- 手元に残す額は「あなたの取り分」＝給料（または店長の給料）＋お店に残す額（`s.ow` → `s.f.keep`）。
- 数字は「計算のもと」（`cbSheet`）で、お店のやり方を選んで決める。
